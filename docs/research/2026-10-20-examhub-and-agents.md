# ExamHub：共享题库路线与 Agent 求职亮点

调研日期：2026-10-20。用户已说明 ExamHub 是自己的暂定名称，不指某个已有产品。目标岗位为全栈／AI 应用开发。本文补充上一份个人课程工作台建议，不代表开始实现或已确定最终规格。

## 推荐结论

选择「个人题库＋可分享题集＋AI 学习教练」。个人题库保证没有社区用户时也有价值，分享让内容可以传播，AI 教练围绕真实作答提供下一步动作。先围绕一门大学计算机课程验证；数据结构允许其他学科，首版不同时运营全学科。

社区和 Agent 是两个不同维度：前者解决内容来自哪里、怎样被复用，后者解决学习过程中怎样决定下一步。无需在两者间二选一，但应限制各自规模。

## 产品范围：轻社区，而不是先建大型广场

首版三条路径：

1. 创建者手工或从资料生成题目，检查修改，发布题集。
2. 学习者通过链接或简单搜索打开题集，练习，保存个人作答与错题。
3. 用户要求检查某主题掌握情况，AI 读取相关记录、选择诊断题、提供提示并安排新题复测。

核心页面为「题集发现」「我的题库」「题集编辑」「专注练习」「学习记录」。题集发现先有搜索、标签与精选样例即可；课程阅读器可作为题目出处侧栏，不必先造完整 Reader。

首版推荐支持单选与简答两类，先交付单选再加入简答。保留已有 Word 导出。允许任意主题标签，但示例和质量评测聚焦一门课程。不做全学科承诺、社交关注流、积分商城、大赛、实时协作、复杂推荐算法或在线代码执行沙箱。

### “答案库”应拆成三种对象

- 作者参考答案与评分量规，绑定题目版本。
- 学习者个人作答、反馈、修改与复测记录，默认私有。
- 用户主动公开的解题说明，可讨论和纠错，不能被多数点赞自动变成正确答案。

这样才能处理多人使用、答案争议与题目修订，避免把参考答案和用户提交混在同一字段。收藏某题集可以跟随作者更新；复制改编则保留独立内容和来源版本。练习记录始终指向实际作答的版本。

公开题目不等于公开上传的教材文件。只有作者选择并允许分享的内容进入公共检索，私有资料证据对无权访问的人不能展开。公开题集至少应有纠错／举报与撤回入口，AI 草稿不自动批量发布。

## 功能亮点与工程证据

| 功能 | 对应技术深度 | 可展示的证据 |
| --- | --- | --- |
| 可维护的共享题集 | 草稿与发布版本、fork 来源、资源授权、事务与冲突检测 | 作者改答案后历史作答保持一致；复制改编不影响原题 |
| 教材依据与题目质检 | 文档定位、结构化输出、检索范围、去重、答案与证据核验 | 人工标注样本上检测坏题，报告误报漏报及每道合格题成本 |
| AI 学习教练 | 工具调用、有限规划、会话恢复、结构化学习状态 | 相同初始题下，根据不同作答采取不同后续动作，可中断恢复 |
| 简答反馈 | 评分量规、分项反馈、证据关联、可纠正评分 | 和人工标注对比一致性，分开统计不同错误类型 |
| 可靠生成任务 | 后台任务、幂等、重试预算、事件流与持久化 | 网络／模型超时后恢复，结果不重复入库 |

登录、收藏、分页、搜索、编辑和响应式是必要基础；它们组合成完整产品，但单独不足以证明 AI 工程能力。实际招聘加分取决于岗位和个人解释能力，本报告没有对招聘市场做统计，也不保证某个框架一定加分。

## Agent 应放在哪里

[Anthropic 的工程说明](https://www.anthropic.com/engineering/building-effective-agents)区分预先规定执行路径的 workflow 和由模型动态选择步骤／工具的 agent，并强调从简单方案开始，权衡成本和延迟。

建议采用一条固定生成质检工作流，加一个有工具的学习教练 Agent。无须多个“出题专家、评分专家、规划专家”互相聊天。

### 生成质检：工作流即可

选定资料 → 分配知识点与题量 → 生成结构化候选 → 校验 → 去重／有限复核 → 作者编辑 → 发布。

客观题答案检查、数量校验、数据库保存和发布规则由程序控制。模型复核只是额外信号；无法确认时标记待检查，不制造确定结论。

### 学习教练：有价值的有限自主选择

用户目标示例：「用 15 分钟检查我对 TCP 的理解，先找薄弱点，再带我练。」

拟议工具接口（设计建议，当前仓库未实现）：

- 查询当前用户相关作答摘要。
- 在允许的题库中按知识点与未见题筛选。
- 检索可访问教材片段。
- 展示一道题并等待真实用户作答。
- 对简答按量规评估，返回可解释反馈。
- 在现有题不足时调用受控出题工作流生成私人候选题。
- 保存本次练习证据与复习建议。

模型可决定先测什么、是否追问、给提示还是解释、是否换一道诊断题。程序决定权限、判分规则、最多调用次数、费用预算、保存一致性和退出条件。每次用户答题后恢复会话，不能让模型代替用户回答并自动跑完整堂课。

例如答对选择题后，询问原因；理由错误时转入概念辨析；资料不足时说明无法确认；答错后可先提示，再按用户选择展开完整解释。结束时报告“本次在哪些题上表现如何”，不把一次答对等同于完全掌握。

若后续选择始终由固定 if/else 决定，就诚实称为自适应学习工作流，不为简历强行改名。若 Agent 不能优于简单规则，就优先保留规则。

### 状态、权限与恢复

持久化当前题目版本、已见题、已收作答、所用证据、下一步状态和调用预算。长期状态保存有出处的作答事实与用户确认的目标，不把完整聊天记录堆进向量库就称为长期记忆。

工具层根据服务端身份限制资源范围，不能让模型传入另一个用户 ID 就读取资料。题目和资料是数据，不能改变工具权限。公开发布和修改他人题目须经过明确的产品授权边界。工具轨迹展示动作和证据摘要，不需要展示模型内部推理。

## 技术选择

| 层 | 推荐 | 何时值得加入 |
| --- | --- | --- |
| 前端 | 保留 Vue 3＋TypeScript＋Pinia，统一一套 UI 组件 | 建设可编辑题目卡片、资料侧栏、保存与恢复状态 |
| API | 初期保留 Flask，使用明确 schema 和服务边界 | FastAPI 可作为个人选型，但换框架本身不加分 |
| 数据 | PostgreSQL，题目与题集版本、作答、任务、权限关系 | 先保证一致性，不为小项目拆微服务 |
| 文档／检索 | PDF.js 阅读，按需解析；跨文档检索再加 pgvector | 用证据定位和检索评测证明效果，中文关键词检索需验证分词 |
| 模型 | 一个默认供应商＋一个实测兼容接口，结构化输出与服务端校验 | 记录各任务实际质量、能力差异、成本和延迟 |
| Agent 编排 | 先明确状态和工具；多轮暂停恢复时可采用 LangGraph | 使用持久化 checkpoint，节点副作用仍需业务幂等 |
| 后台任务 | 独立 worker＋持久化任务；需要成熟队列再引入相应组件 | 模型耗时不占用前端请求，支持取消、重试和重连 |
| 可观测／评测 | 先记录结构化调用日志；需要 UI 时可选 Langfuse | 固定样本回归、模型／提示词版本、成本与失败定位 |

[LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence)提供 checkpoint 与跨会话存储；[interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)支持暂停等待外部输入，恢复时节点可能重跑，因此不会自动解决重复写入。[Langfuse](https://langfuse.com/docs/observability/overview)可用于模型应用追踪；是否部署应考虑额外维护成本。

本轮未确定依赖版本或完成组件许可证审计。不要同时加入 LangChain、LangGraph、多个 Agent 框架、独立向量库、Kafka 和 Kubernetes。MCP 只在需要给外部 Agent 复用工具时评估，内部函数调用无需先包装成 MCP。

## 如何验证真正的求职亮点

准备一门课程和可公开的题集，分别验证以下三层：

1. 产品与数据：A 发布，B 练习，B 复制修改，A 改参考答案；核对权限、来源和历史成绩。
2. AI 质量：人工标注正常题、错误答案、歧义题、无依据题、重复题；比较纯提示词与校验流程的正确率、误报、漏报和合格题成本。
3. 教练行为：固定规则教练作为基线，测试工具选用、等待用户、证据使用、停止条件、恢复和开销；加入资料不足、答案冲突、用户中途改变目标等场景。

在模拟轨迹上通过行为测试只能证明工程行为，不证明学习有效。真实教学效果需用学习者未见过的复测题和人工评分观察；小样本试用报告实际结果，不宣称统计显著提升。用于开发调优的样本与最终测试集分开，避免记住评测答案。

建议求职 v1 的停止边界：一个样板方向、两种题型、一条发布／复制／练习链路、一条有来源的生成质检链路、一个可恢复的教练 Agent；有演示数据、CI、评测报告和一轮真实用户反馈。未完成这些前不扩展为全学科社区。

推荐面试演示：「从他人的公开题集中开始练习 → AI 根据实际作答调整下一题 → 回到资料澄清误解 → 发现有争议题并提出纠错 → 作者发布修订版 → 历史作答仍可解释」。可分步录制，不必第一天全部实现。

这份建议的价值判断是工程与产品分析，不是招聘录用承诺。下一步应确定首个样板学科及 MVP 范围，再进入详细设计。本轮仅调研与文档整理，未修改业务代码。
