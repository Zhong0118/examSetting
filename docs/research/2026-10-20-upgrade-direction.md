# examSetting 升级方向与求职交付边界

调研日期：2026-10-20。目标岗位：用户已确认全栈／AI 应用开发。

本文是调研建议，不是已批准的开发规格。已检查本地源码、启动前端、查看桌面与 390px 手机布局，并执行完整前端构建；未调用仓库中的模型密钥，未验证真实生成质量。竞品主要依据官方文档、作者仓库及部分源码，未登录实测商业产品。功能宣传、推断和本项目建议应分开理解。

## 1. 建议决策

将项目升级为面向大学生的「课程资料与练习工作台」：围绕一门课，把教材、讲义、已有题目、练习记录组织起来，使每道生成题能追溯原文、被修改、被复习。

建议首个样板选择用户熟悉、可以人工判断答案的一门计算机课程，例如计算机网络。不是承诺只支持该课程，而是先用它建立真实样本和验收基线。第一版输入以文本 PDF 和粘贴文本为主，题型先做好单选，再加简答。扫描件、复杂数学公式、完整教材题库自动拆分都是后续独立问题。

推荐定位语：**把课程资料变成有依据、可维护、可持续练习的个人题库。**

产品对象以课程为中心，教材是知识依据，已有题库是练习资产，出题是其中一个动作。可以借鉴 Reader 的阅读联动，但不必复制它的桌面端、翻译、文献元数据或 CLI 桥接。

| 路线 | 好处 | 代价与问题 | 判断 |
| --- | --- | --- | --- |
| 精致的一次性出题器 | 改造快、保留旧使用方式 | 与通用对话模型和现成工具重叠，持续使用动机弱 | 作为快速出题入口保留 |
| 课程资料＋可追溯题库＋练习 | 可以逐步扩展，也有明确全栈与 AI 工程问题 | 必须认真处理文档定位、题目质量与数据生命周期 | 推荐主线 |
| 完整教育平台／全能阅读器 | 展示功能多 | 用户、内容、协作、运营和客户端范围过大 | 暂缓 |

几十个 star 是已有传播基础，不等于活跃用户或需求验证。先邀请少量现有关注者完成真实任务，观察他们是否回来使用，别根据 star 数决定做大型产品。

## 4. 核心用户流程

1. 创建课程并导入教材／讲义，确认目录或手动划分页码范围。
2. 打开章节阅读，从本章或选区生成一小组题。
3. 系统保存草稿，检查格式、重复和引用；用户可改题、停用或确认。
4. 进入专注练习，答案默认隐藏，作答自动保存。
5. 答错时先给提示，再展示解析与教材出处，可以跳回原文。
6. 加入复习队列，用原题或同知识点新题再次检查。

例如：阅读“TCP 拥塞控制” → 生成 5 道题 → 做错其中一道 → 查看教材相应页 → 选择原因“概念混淆” → 下次练习一道场景不同的新题。错因可以由 AI 建议，但需允许用户修改。少量作答只能展示练习表现，不能直接宣称掌握度精确诊断。

已有题库和模型生成题必须分别标明来源。教材中的事实用于支撑答案，已有试题可以提供题型和覆盖参考，不能自动将其视为事实标准。若二者冲突，应展示冲突并允许人工处理。

## 5. 功能优先级与明确边界

| 阶段 | 做什么 | 验收 |
| --- | --- | --- |
| 基线修复 | 密钥配置、构建通过、统一 API 地址、结构化题目、持久化和资源归属 | 两个用户不会串题；刷新不丢题；异常可解释 |
| 最小闭环 | 课程、文本 PDF、页码范围、单选题、题目编辑、练习、错题回看、示例课程 | 陌生用户无需写提示词即可从资料进入练习 |
| 求职主版本 | 原文证据跳转、题目版本、任务恢复、质量评测、费用和延迟记录、有限多模型支持 | 能复现质量改进和失败恢复，有完整部署／演示材料 |
| 需求验证后 | 简答评分量规、CSV/JSON 题库导入、组卷导出、间隔复习、跨章检索 | 对应真实反馈，不为凑功能而做 |
| 暂缓 | 全格式 OCR、自动解析任意试卷、语音导师、视频生成、社区、商城、课堂管理、桌面多端、知识图谱 | 单独立项，不能阻塞主版本 |

保留旧用户熟悉的快速出题和 Word 导出，但把它们作为工作台内操作。第一版不需要同时完整支持六种题型。若用户验证发现主要需求是教师组卷，应重新调整定位，不要一边做学生复习、一边做完整教师平台。

## 6. 页面与交互重构

全局入口建议只有「课程」「复习」「设置」。课程内有资料、题库和练习记录，避免再造多套重复导航。

| 页面 | 主要内容与动作 |
| --- | --- |
| 课程工作台 | 最近课程、继续阅读、待复习数量、添加资料；首次进入有可体验的示例课程 |
| 章节阅读 | 左侧目录，中间正文，右侧可收起的题目／笔记栏；选区直接解释或出题 |
| 题库 | 按章节与状态筛选，查看出处，编辑题干、答案和解析；支持停用有争议题 |
| 专注练习 | 一次一题、键盘操作、自动保存；提交后再显示答案和依据 |
| 结果与复习 | 本次错误、未覆盖章节、到期题；明确下一步是回原文或继续练习 |
| 模型设置 | 简洁的默认连接和连接测试；高级配置折叠，不把参数墙放在首页 |

视觉方向：白色主背景、黑灰正文、蓝色主操作；去掉装饰性大背景、厚重阴影和彩色按钮竞争。采用清晰字号层级、统一边框和适合长文阅读的行宽。数学公式和代码保持高可读性。用开源 SVG 图标而非 emoji。

动效要覆盖进入、切换、退出和交互反馈，但统一发生在容器或共享元素上，不让每个字单独飞入。课程卡片到章节标题、选中文本到题目卡片、题目提交到解析展开都保持位置连续。按钮按压、焦点、高亮跳转和任务完成都有轻量反馈。建议普通反馈约 120–180ms、面板切换约 180–260ms，作为待调试初值；遵循减少动态效果偏好，长任务不用伪造百分比。

手机改为单栏：目录抽屉、正文主视图、题目作为独立页面或底部面板。不得把桌面三栏缩小塞进手机。第一轮视觉设计应围绕「阅读→出题→作答→回原文」这条实际路径，不先做营销首页。

## 7. 全栈／AI 应用方向最值得做深的技术

### A. 证据贯穿数据生命周期

解析时保留文件版本、PDF 实际页索引、页内片段和可用的定位信息。生成题关联服务端已有的片段 ID，页面显示的引用由系统解析，不能让模型随口生成页码。纸面页码与 PDF 页索引可能不同，需要区分。

基础校验先判断引用存在；质量评估还要判断引用是否真正支撑答案，二者不可混为一谈。题目修订产生版本，历史作答继续绑定原版本，避免修改答案后历史成绩悄悄变化。

### B. 可评测的生成流程

按已选章节准备证据 → 按知识点覆盖分配题量 → 生成结构化候选 → 确定性校验 → 必要时有限模型复核 → 进入题库。

确定性校验包括题型字段、答案索引、选项重复、题量、证据 ID 归属与文本存在、完全重复题。语义重复和答案一致性可以后加，并用标注样本选择阈值。模型复核不是正确性证明，不能输出没有校准依据的“98% 置信度”。

章节较短时直接提供章节文本即可；长章节按小节分批，控制覆盖与上下文预算。整本书出题或跨章节问答出现后，再考虑检索。检索必须先按用户、课程、教材和章节约束候选，避免串库；不要只用相似度最高的几段代表整章考点。

### C. 可靠的后台任务与调用成本

持久化任务状态、已完成批次和错误原因，支持重试、取消和刷新后恢复。一次生成作为任务，逐题校验入库；网络断开不应导致已完成题丢失。重试有幂等约束和次数上限，避免重复题与重复付费。

记录模型、提示词版本、解析版本、token 用量、耗时、重试与估计费用；不能取得真实账单时明确标为估算。后台工作进程可与 Web API 使用同一代码库，初期无需微服务。

### D. 客观判分与可解释复习

单选／判断用确定性逻辑评分。简答再引入评分量规和逐项依据，标明 AI 建议分，允许修改。复习先用透明的到期规则，保留用户自评与首次／复测表现；有足够需求再评估成熟间隔复习实现。不要为了简历自行发明“学习大脑”。

## 8. 技术栈与开源复用

建议继续 Vue 3＋TypeScript，后端初期保留 Flask，新增服务层、数据模型和独立任务进程。现有规模没有证据表明框架必须更换；FastAPI 可以是后续团队偏好，但不是项目亮点。

公开 Web 版本建议使用 PostgreSQL 管理用户、课程、题目、作答与任务；文件先放部署持久卷，小规模无需立即加对象存储。向量检索需要时使用 [pgvector](https://github.com/pgvector/pgvector)，避免再运行独立向量数据库。中文关键词检索需要验证分词能力，不能默认 PostgreSQL 内置文本检索就解决中文。

| 候选 | 可用部分 | 取舍 |
| --- | --- | --- |
| [PDF.js](https://github.com/mozilla/pdf.js)，Apache-2.0 | 阅读、页码导航、文本层 | 优先复用，仍需实现自己的题目证据定位 |
| [Docling](https://github.com/docling-project/docling)，MIT | 结构、版面、表格与 OCR 等文档处理 | 用真实样本验证定位和中文效果，复杂依赖及模型下载有部署成本 |
| [MarkItDown](https://github.com/microsoft/markitdown) | 多格式转 Markdown 的轻量候选 | 纯 Markdown 输出不能自动满足页码溯源，不作为唯一证据格式 |
| 已有 Element Plus 或 [shadcn-vue](https://www.shadcn-vue.com/) | 表单、弹层、基础组件 | 二选一建立新页面规范，别继续叠加组件库 |
| [Exameow](https://github.com/heshengtao/exameow)，Apache-2.0 | 同栈题库／练习交互和解析实现参考 | 可阅读借鉴具体模块，不建议复制完整应用再包装成原创 |

这些是候选，未做统一解析速度／质量对比。正式采用前固定版本、保留归属并核查选用部分与模型资产许可。Reader 作为交互研究对象，整体代码复用需另行核验授权。

## 9. 模型接入与公开体验

将用户的“公共的模型选择”暂理解为：不再绑定个人密钥和单一厂商，让他人可以方便使用。兼容多厂商和免费公共额度是不同决策。

建议提供三层体验：

1. 无 Key 示例课程：可直接阅读、练习已有题，不产生模型费用。
2. 有限公共试用：服务端持有平台 Key，按用户限额和并发控制，公开清晰的资料发送范围。
3. 自部署／自带 Key：按供应商地址、Key、模型配置，提供连接和能力测试；生产实例不默认接受任意内网目标地址。

先支持一个官方默认供应商及一个经实际测试的兼容接口。统一“出题、解释”调用和返回结构，记录是否支持结构化输出、视觉输入、流式。兼容接口的请求参数和能力可能不同，不能只改 base URL 就承诺所有模型可用。

日常模式显示“快速／精细”等任务偏好即可，技术设置中保留实际模型。默认模型由固定评测集下的合格题成本、延迟和可靠性选择；本轮未做模型横评，不指定所谓最佳型号。模型复核、视觉解析和 embedding 也无需全都交给最高价模型。

## 10. 什么程度适合放简历

推荐交付的是可公开演示、可自部署、经过小范围真实使用的完整 v1。没有必要等待成为商业平台，也没有必要达成某个 star 数。

验收目标建议如下，均为待实现目标，不是当前成绩或行业招聘硬门槛：

- 一门样板课程、3–5 个章节，授权或原创演示资料；陌生用户能独立完成导入、练习、纠错和复习。
- 准备约 100–200 条人工核验样本，覆盖正确题、坏题、证据不足、重复和格式错误；另有坏文档和失败任务用例。
- 对照旧式纯提示词方案、加来源方案、加校验方案，固定模型、题量和资料；保留独立测试集，多次运行，记录不确定性。
- 分开报告格式有效率、答案正确率、引用存在率、引用支持率、重复率、章节覆盖、p50/p95 延迟和每道合格题成本；不要只报告原始生成数量或模型自评分。
- 建议寻找 5–10 位真实试用者，观察 1–2 周，记录首次完成率、再次练习和具体问题，作为定性试用证据；小样本不宣传统计显著或成绩提升。
- 验证两用户隔离、重试不重复入库、刷新恢复、限额失效保护和题目改版后的历史记录；构建、类型检查与关键路径测试进入 CI。
