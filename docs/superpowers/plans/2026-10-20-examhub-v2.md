# ExamHub V2 Implementation Plan

> Use subagent-driven-development for separate modules; coordinator owns AI integration and acceptance.

**Goal:** PDF → page-grounded questions → explainable quality reports → repeatable evaluation.
**Architecture:** Existing Vue/Flask/SQLite, bounded PDF parsing and private file storage. Two independent workers implement document service and frontend; coordinator implements AI citation and quality/evaluation integration.
**Tech Stack:** pypdf, PDF.js, Vue 3, Python unittest, Node tests.
**Spec:** docs/superpowers/specs/2026-10-20-examhub-v2.md

## Global Constraints

- Current branch codex/examhub-v2, based on committed V1; no automatic push or merge for V2.
- Keep UI style and V1 tests, private document access, no paid external model calls for validation.
- No OCR, semantic correctness guarantee, or Agent claim. Report PDF physical pages and rule metrics honestly.

## Rulings / progress

- User explicitly approved implementing V2; no repeated approval gate.
- Parallel workers have disjoint write sets. Task 1 selection returns source + pages; Task 2 consumes canonical camelCase spec; Task 3 integrates on those stable interfaces. Parent alone edits app/repository and AI.
- PDF original access remains owner-only even when a question set is shared. Shared questions include only citation snapshot; UI explains restriction.
