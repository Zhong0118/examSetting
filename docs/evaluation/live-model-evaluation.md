# 真实模型教学评测与当前证据

本轮将“工具能运行”“反馈教得如何”“用户是否学会”拆开记录。真实模型负责动作决策，学生回答固定，评分与真人学习研究分别保存。三轮共55次真实调用，四个原创场景均已有实际运行；循环、参数错误、无出处提前结束和成功轨迹一并保留。成功轨迹来自不同提示版本，尚未证明最终提示的总体稳定率或真人学习提升。

## 复用与评测设计

开发前检查了 [AgentEvals](https://github.com/langchain-ai/agentevals)（MIT，轨迹匹配与模型裁判）和 [Promptfoo](https://github.com/promptfoo/promptfoo)（MIT，模型对比及评测界面）。它们提供通用能力；本项目已有教学引擎、HTTP 适配器与持久化，因此直接复用现有链路，保留标准消息和 JSON 导出，避免额外编排层。将来需要跨供应商大批量实验时可接这些工具。

设计借鉴 [Anthropic 的 Agent 评测说明](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)：记录完整轨迹、区分 trial 与检查项，并保留失败；本项目并不要求模型逐步匹配某条标准轨迹。模型可以自行选题、检索、反馈、追问或结束，检查发生在实际事件和最终状态上。

真实调用使用 [DeepSeek 官方模型名](https://api-docs.deepseek.com/quick_start/pricing/) `deepseek-flash`，本轮按 [thinking 参数](https://api-docs.deepseek.com/guides/thinking_mode/)关闭思考模式。报告保存请求参数和供应商实际返回的模型字符串，不假定可从别名确认不可变权重版本。不保存供应商独立的 `reasoning_content` 字段。原始 `content` 中可识别的 `<think>` / `<analysis>` 片段也会脱敏；不能声称能识别任意未标记自然语言的内部推理。共用脱敏入口对畸形引号中的转义文本最多展开8层探测；发现当前密钥或已识别思考标签时，保守隐藏该不安全字符串，超过展开上限也隐藏。正常无敏感内容保持原字节，严格执行始终解析原始协议，不能用脱敏结果挽救非法动作。

## 如何复现

在“教学教练”底部的“真实模型教学评测”选择场景、每策略重复数和调用预算，确认后启动。四个原创场景使用固定的题目、初始历史、学生主回答和追问理由。规则基线与模型使用同一引擎及同一输入条件。每个模型 trial 最多10次调用、每个 trial 最多40步；整作业最多20次，预算不足明确保留未完成项。

重复运行可暴露波动，每个 trial 保留结果；当前样本很小，没有置信区间、显著性或泛化结论。固定学生不会因反馈改变其答案，因此不能测学习收益。数据集由开发者编写，尚不是独立留出集。

启动先持久化请求编号，断网使用原编号重放，避免重复计费。刷新只读；取消与动作写入采用同一提交边界；派发标记提交后视为在途，取消仍可能留下计费请求。派发前取消可阻止适配器调用，但已预留额度不回退；返回后若取消先提交，迟到动作不会写入教学状态。重启标记中断，不自动续跑付费请求。SQLite 在网络前预留调用额度和当前所有者，限制每用户40次/小时、实例120次/小时；这是评测模块独立额度，不能与教学会话额度合称跨模块总配额。当前单进程最多两个评测作业，每用户一个。

每份报告保存数据集 SHA256、选定场景快照、提示 SHA256、判据版本、生成参数、实际消息、content、工具结果、token 用量及耗时。正常输出逐字保留；含密钥或可识别思考标签的异常输出保存脱敏表示并标记，不提供可逆的原始敏感内容。调用前计数，因此供应商错误和中断也占额度；未返回 usage 即为未知。外部调用不承诺 exactly-once，不推算人民币费用。当前历史接口最多返回最近10个完整报告，规模扩大后再分页和按需读取轨迹。

## 2026-10-20 首轮实测

[原始报告](runs/2026-10-20-deepseek-smoke.json)包含20次真实 DeepSeek 请求与返回，规则调用数为0。两场景、每策略各一次，共4个 trial；没有付费模型裁判或额外学生模型。首轮授权20次全部用完，当轮没有追加请求；下文的复测来自用户另行授权的20次预算。

| 策略 | 完成 trial | 行为检查通过 | 模型调用 | 返回 total_tokens |
| --- | --- | --- | --- | --- |
| 规则教练 | 2/2 | 8/13 | 0 | 不适用 |
| DeepSeek 教练 | 0/2 | 3/13 | 20 | 10866 |

这份历史报告使用 `live-behavior-v1` 判据，其中“动作均通过校验”还要求正常结束，因此预算耗尽也判未通过；原始3/13保留。当前 v2 将动作合法性与完成分开，后续对比必须使用相同判据版本，不能直接比较这两个版本的汇总分数。

“完成”只指执行正常结束，不是通过所有教学目标。规则模式未实现证据检索与理由追问，因此不能通过全部目标。真实模型这次也没有形成完整反馈：

- TCP 场景连续10次 `read_history`，没有问出题目。
- 事务场景完成一道题并追问理由；随后中文查询与英文摘录不匹配，连续检索无结果，最后耗尽预算。

仅凭这次报告不能判定模型通常不如规则，也不能推出改用另一个模型必然解决。它说明旧上下文与检索设计对这两个实际轨迹不够有效。报告保留失败、原提示哈希和原数据集哈希，不拿修复后的代码重算成成功。

## 根据失败做的修正

1. 给模型显式提供 `historyRead`、最近6个工具摘要和最近一次检索的 query/resultCount，帮助它区分已完成步骤；提示中要求已读历史不重复读，检索无依据时承认不足并完成反馈。
2. 词面检索同时索引已答题的题干与主题，让中文题干关键词可以定位附带的英文摘录。返回仍是原始 source/citation；不翻译、不合成新证据，也不宣称跨语言语义检索。未答题不进入索引。
3. 新增回归验证上述字段、中文题干查找原英文引文，以及真实本地 HTTP 替身通过全部六个工具的完整协议。

这四次沿用原 TCP、事务场景，题目、原文、历史、目标和固定学生回答均未修改。数据集 SHA256 始终为 `eabf2d8b14557fa6e3ba966d079db27dadcfd892cd68f6d1d8524cbcabdfe011`；供应商、模型别名和生成参数相同（`deepseek-flash`，temperature=0.4，max_tokens=2000，thinking=disabled），使用 `live-behavior-v2` 判据。提示在第一次失败后修正，作业预算也有差异，因此不把四次合并包装为同一策略的稳定率。

第一次复测已从读取历史推进到提问、真实接收固定回答并检索到原文，但模型把 `message`、`evidenceIds` 放在顶层，没有放入 `args`。服务端严格拒绝该动作且未改写教学状态。随后仅在系统提示中明确顶层必须为 `{tool,args}`，所有参数放进对象 `args`，并给出合法反馈/结束格式和不可照抄占位证据 ID 的说明。没有增加宽松 JSON 修复或替模型编排动作；当时新模型教学会话的策略标签为 `tutor-v3.3`。

修正后的 TCP 轨迹为读取一次历史→提问→检索→带引用反馈→追问并接收理由→总结结束。两次事务轨迹均为提问→追问并接收理由→检索→带引用反馈→总结结束。TCP 反馈区分可靠性与低延迟；事务反馈区分原子性与隔离性。中文事务查询通过已答题题干关键词定位原英文摘录，引用仍指向同一个原始证据 `ev-bb8a9d13ba8756630348fe30`，没有翻译或合成原文。这三次均未重现重复读取历史或空检索循环。

`backend/tests/test_tutor_recordings.py` 固定核对这四份报告及4/6/5/5次调用，并与模型步骤数交叉验证。从原始 `content` 重新解析动作，用相同引擎和固定学生输入离线执行，逐步核对工具/作答返回值、提示哈希、作答、事件与总结；第一次的非法动作也必须被拒绝且状态不变。它不联网、不重生成报告、不重算历史判据。首轮20次和本轮20次的记录均保留原样。

这轮证据支持“两个已知问题在所测轨迹中未再出现，修正后3/3次完成全部行为目标”。当时仅覆盖两个开发者编写场景，其中 TCP 修正后只有一次；不能据此宣称模型总体完成率100%、已无循环风险或教学效果提升。其余场景与后来补做的片段评分见下文，不把工程复核当作独立教学评分。

## 教学质量与真人学习收益

报告支持随机 blindId、打乱顺序且移除策略/模型字段的复核包，四个维度各0–2分：事实正确、证据支持、误区诊断、下一步可执行。完整报告保留映射与逐项理由。风格仍可能暴露来源；这是辅助遮蔽，不是正式双盲。复核写入带版本校验。

首轮四条结果由只读取遮蔽包的另一 AI 助手复核，记录为 `ai-assisted`。两个未形成反馈的模型 trial 四项均为0；规则反馈事实正确但诊断与行动建议不足。之后由另一位未参与开发的 AI 助手，仅依据随机打乱的策略遮蔽包，补评全部八条同场景复测记录，包括失败。原始执行快照不改写，包、文件哈希、逐条理由和复核结果保存在 [复测评分附件](reviews/2026-10-20-retest-feedback.json)，并通过带版本校验的 API 保存到本地作业。

当前遮蔽协议只提供反馈与追问事件，不包含 finish 总结，因此分数只评价这些片段。事务两次的反馈片段在行动建议维度均得0；不能据此称整段会话没有复习建议，因为结束总结不在评分材料内。一次事务反馈提到未提交数据的例子，事实正确但超出所附短句，证据维度得1；成功的工具调用不自动等于反馈的每句话都有引用支持。评分保留这些不足，没有只呈现高分。没有独立真人评分，也没有裁判与专家一致性校准，因此这些分数是探索性辅助复核证据，不能包装成专家教学质量结论。

第三轮由另一位新 AI 助手使用同一量表、仅阅读策略遮蔽包，补评全部十条规则／模型记录。实际输入、快照文件哈希、逐项理由和保存的评分见 [边界场景评分附件](reviews/2026-10-20-edge-feedback.json)。下表给出全部五个模型片段分数（每项满分2）：

| 模型 trial | 事实正确 | 证据边界 | 误区诊断 | 下一步 |
| --- | --- | --- | --- | --- |
| 无出处1：未交付反馈 | 0 | 0 | 0 | 0 |
| 资料指令1 | 2 | 2 | 2 | 0 |
| 无出处2 | 2 | 2 | 2 | 1 |
| 资料指令2 | 2 | 2 | 2 | 0 |
| 无出处3 | 2 | 2 | 2 | 2 |

无出处1的0分表示可见反馈缺失，不表示它的结束总结包含事实错误。无出处成功片段的证据维度得2，是因明确承认无教材、未伪造来源或掌握判断，不能解读为“已有教材验证”。资料指令两次行为检查全部通过，行动建议仍得0，说明工程闭环完成与反馈是否给出可操作任务属于不同问题。评分没有用作自动行为判据，也没有在独立 AI 复核后补改回答以抬高分数。新增18条复核均明确为 `ai-assisted`，与首轮四条辅助复核分别保留。

真人学习证据的下一步是 [匿名研究协议与 CSV 分析](learning-study.md)：匹配教学内容和时间，按实际研究方案分组，独立完成等价前测/后测及延迟测验。当前模板只有表头，没有真实参与者；分析命令会返回零样本和空均值，不生成提升数据。

## 求职展示与下一阶段优先级

当前可以展示：真实执行轨迹、固定条件的规则对照、失败保留分母、预算/幂等/恢复、证据边界，以及从真实失败、最小修正到同场景复测和离线回放的决策链。可以准确描述追加20次调用中一次格式失败与后续三次完整闭环，不写成总体稳定率。面试时应能解释为什么“所有单元测试通过”仍不足以证明模型会教，为什么模拟学生不能代替真人学习研究。

后续按顺序补：固定最终提示后重测全部四场景并增加重复；由未参与开发的人新增留出场景并独立人工评分；覆盖总结的完整反馈质量复核；小规模真实试用和前后测。针对循环是否需要执行层拦截，应在更多轨迹中测误阻断和收益；当前提示约束不等于执行层禁止。最后再根据观测决定是否需要向量检索、模型比较或更复杂教学策略，当前没有必要继续堆 Agent 数量、排行榜或复杂社区功能来替代这些证据。
